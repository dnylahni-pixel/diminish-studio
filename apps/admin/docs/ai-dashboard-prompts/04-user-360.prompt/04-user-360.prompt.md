# Prompt 04 — User 360

Implement a read-only enterprise user detail route at `/users/[userId]`. Do not add mutations yet.

## Project Capsule

- Next.js 16 App Router; treat `params` as `Promise<{ userId: string }>`.
- Reuse existing UI primitives. Do not build new generic Card, Tabs, Timeline, Table or Badge primitives.
- Keep Server Components for data; use client leaves only if Tabs require them.
- Return `notFound()` for invalid or missing numeric users.

## Data

User identity:

- `users`: `id`, `username`, `email`, `avatarUrl`, `bio`, `preferredInstrument`, `createdAt`, `storageUsedBytes`, `storageQuotaBytes`

Subscription:

- `subscriptions`: all lifecycle/status/date fields
- `plans.name`, `plans.code`
- `planVersions.versionNumber`, `title`
- `planPrices.amount`, `currency`, `billingInterval`, `billingIntervalCount`
- recent `subscriptionEvents`

Credits:

- `creditAccounts`: status, balance, reservedBalance, lifetimeGranted, lifetimeUsed
- recent `creditLedger`: entryType, amount, balanceAfter, description, createdAt
- active `creditGrants` and `creditReservations`

Billing:

- recent `invoices`: invoiceNumber, status, totalAmount, amountPaid, amountDue, currency, dueAt
- recent `transactions`: type, status, amount, currency, processedAt, createdAt
- `trials`
- `couponRedemptions`

## Page Composition

1. Breadcrumb: Users / user identity.
2. Identity header:
   - large `Avatar`
   - username, email and numeric ID
   - subscription `StatusIndicator`
   - joined date
   - no fake Ban/Suspend status
3. Four compact summary cards:
   - Current Plan
   - Available Credit
   - Lifetime Credit Used
   - Storage Usage
4. Tabs in this exact order:
   - Overview
   - Subscription
   - Credits
   - Billing
   - Activity

## Tab Recipes

- Overview: two-column layout using `Card` + `DescriptionList`; account details left, commercial snapshot right.
- Subscription: subscription summary, current period, pricing, scheduled changes, then `Timeline` from subscription events.
- Credits: balance cards, grants/reservations, then ledger table.
- Billing: invoices table followed by transactions table.
- Activity: commercial activity only—trial, coupon redemption, subscription and credit events. Do not expose Songs/Artists/Chords.

## UX Rules

- Show at most 10 recent rows per embedded table with a `View all` link to its domain page.
- Use exact date tooltip and readable relative time.
- Empty subsection uses small `EmptyState`, not hidden whitespace.
- Do not render buttons that pretend to mutate data.
- Amount and credit formatting must be consistent with other pages.

- Invalid ID and missing user resolve correctly.
- All joins are user-scoped.
- No private password hash, provider payload, payment token or sensitive metadata is rendered.
- No N+1 query.
- Build and lint succeed.
