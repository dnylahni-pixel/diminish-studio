# CVE-2026-53571 in vite 7.3.3 (dev-server fs.deny bypass, Windows)

**ID:** vuln-0004
**Severity:** HIGH
**Found:** 2026-08-08 16:28:10 UTC
**Target:** Diminish Studio (diminish-studio monorepo, apps/diminish-studio + apps/mockup-sandbox Vite dev tooling)
**Package:** vite
**Ecosystem:** npm
**Installed Version:** 7.3.3
**Fixed Version:** 7.3.5
**CVE:** CVE-2026-53571
**CWE:** CWE-22
**CVSS:** 7.5
**Fix Effort:** Trivial

## Description

The Diminish Studio user app pins `vite@7.3.3` (declared as `vite: catalog:` with catalog specifier `^7.3.2`), which falls in the affected range `>= 7.0.0, <= 7.3.4` of CVE-2026-53571 — a `server.fs.deny` bypass on Windows alternate paths in the Vite dev server allowing arbitrary file reads. Fixed in `vite@7.3.5`.

## Evidence

**Advisory evidence:** `CVE-2026-53571` applies to `vite` at installed version `7.3.3`. The advisory is fixed in `7.3.5`.

**Usage analysis:** imported by application code; affected API usage unconfirmed. Vite is a direct devDependency and is exercised at development time: apps/diminish-studio/package.json:73 (`"vite": "catalog:"`) with the catalog specifier `^7.3.2` at pnpm-workspace.yaml:30, resolved to `vite@7.3.3` at pnpm-lock.yaml:6628. The dev server is imported/configured in apps/diminish-studio/vite.config.ts:1 (`import { defineConfig, loadEnv } from "vite"`) and apps/mockup-sandbox/vite.config.ts:1. The affected API (dev-server `server.fs.deny` enforcement) was not exercised with a Windows-specific exploit during this assessment; import-level reachability only. This is a prioritization signal from static analysis, not a proof of exploitability or of safety.

## Impact

On a Windows development machine, a malicious website visited by the developer can issue requests to the local Vite dev server (which binds to localhost and answers cross-origin requests) and read files outside the allowed project root via alternate path syntax, disclosing source code or local configuration files including secrets from local environment files.

## Technical Analysis

The `default` catalog in `pnpm-workspace.yaml:30` pins `vite: ^7.3.2`, which resolved to `vite@7.3.3` in `pnpm-lock.yaml:6628` and is consumed by `apps/diminish-studio` and `apps/mockup-sandbox` (via `@vitejs/plugin-react@5.2.0`, `@tailwindcss/vite@4.3.0`, and `vite-plugin-pwa@1.3.0`, all keyed to `vite@7.3.3` in the lockfile). CVE-2026-53571 (GHSA-fx2h-pf6j-xcff) is a `server.fs.deny` bypass using Windows alternate paths, allowing unauthenticated arbitrary file read from the dev server; the installed 7.3.3 is within the affected range `>= 7.0.0, <= 7.3.4` and the fix is 7.3.5.

## Remediation

Upgrade `vite` to `>= 7.3.5` by updating the `vite` entry in the `default` catalog of `pnpm-workspace.yaml` (currently `^7.3.2`) and re-running `pnpm install` to refresh `pnpm-lock.yaml`. Verify the dev server still boots and HMR works after the bump.

## Assumptions

Verified against the GitHub Security Advisory (GHSA-fx2h-pf6j-xcff): affected `>= 7.0.0, <= 7.3.4`, patched in 7.3.5, CVSS 3.1 base score 7.5 (AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N). The vulnerability is limited to the Vite development server on Windows (bypass of `server.fs.deny` via Windows alternate paths); it does not affect production builds or Linux-based development. The sandbox and CI environments are Linux, so the vector is not exploitable there, but any Windows-based local development machine running `pnpm dev` is exposed.
