# CVE-2026-53632 in vite 7.3.3 (NTLMv2 hash disclosure via launch-editor, Windows)

**ID:** vuln-0005
**Severity:** MEDIUM
**Found:** 2026-08-08 16:29:04 UTC
**Target:** Diminish Studio (diminish-studio monorepo, Vite dev tooling)
**Package:** vite
**Ecosystem:** npm
**Installed Version:** 7.3.3
**Fixed Version:** 7.3.5
**CVE:** CVE-2026-53632
**CVSS:** 5.5
**Fix Effort:** Trivial

## Description

The Diminish Studio monorepo resolves `vite@7.3.3` in `pnpm-lock.yaml`, which falls in the affected range `>= 7.0.0, <= 7.3.4` of CVE-2026-53632 — NTLMv2 hash disclosure via UNC path handling in the bundled `launch-editor` component of the Vite dev server (Windows only). Fixed in `vite@7.3.5` (and `launch-editor@2.14.1`).

## Evidence

**Advisory evidence:** `CVE-2026-53632` applies to `vite` at installed version `7.3.3`. The advisory is fixed in `7.3.5`.

**Usage analysis:** imported by application code; affected API usage unconfirmed. Vite is a direct devDependency resolved at pnpm-lock.yaml:6628 (`vite@7.3.3`), declared via the `default` catalog at pnpm-workspace.yaml:30 (`vite: ^7.3.2`) and consumed by apps/diminish-studio (package.json:73) and apps/mockup-sandbox. The dev server is configured in apps/diminish-studio/vite.config.ts:1 and apps/mockup-sandbox/vite.config.ts:1 (`import { defineConfig } from "vite"`). The affected `launch-editor` UNC-path behavior was not triggered during this assessment; import-level reachability only. This is a prioritization signal from static analysis, not a proof of exploitability or of safety.

## Impact

On Windows, a crafted request to the local Vite dev server can cause the `launch-editor` integration to open a UNC path, triggering an NTLMv2 credential hash disclosure to an attacker-controlled server — a credential-leak primitive usable for relay or offline cracking of the developer's Windows account.

## Technical Analysis

The advisory GHSA-v6wh-96g9-6wx3 lists `vite` in the affected range `>= 7.0.0, <= 7.3.4` (patched 7.3.5) alongside `launch-editor <= 2.14.0` (patched 2.14.1). The installed `vite@7.3.3` (pnpm-lock.yaml:6628) is within the affected range. The vulnerability concerns the Vite dev server's `launch-editor` handler: a crafted request can reference a UNC path, and on Windows the editor-launch logic causes the client to authenticate to the attacker-controlled host, disclosing the NTLMv2 hash. Development-time only; production builds are unaffected.

## Remediation

Upgrade `vite` to `>= 7.3.5` by updating the `vite` catalog entry in `pnpm-workspace.yaml` (currently `^7.3.2`) and re-running `pnpm install` to update `pnpm-lock.yaml`. Alternatively, pin `launch-editor` to `>= 2.14.1` via an override. No production impact; the fix addresses the Windows dev-server exposure.
